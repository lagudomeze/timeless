# 装备：容器、内容与属性叠加（M27）

> ✅ **已落地**（`src/equipment/`）。本文记的是**最终形态**，并标出每一处
> **与最初设计稿的偏差**（第五节 / 第七节 / 第九节）——那些偏差都是落地时才看清的。
>
> 关系模型的通用规则见 [relations.md](relations.md)；数值外置见 [config.md](config.md)。

## 一、这一版解决了什么

装备**不引入新的战斗机制**。它是「往单位身上挂加成」的**来源**：命中公式、调度器、
技能目录都照常读它们本来就读的组件，一行不用为装备改。

```text
PC（单位根 = 脚底）
 ├─ 槽位实体 EquipmentSlot { slot }      ← ChildOf(pc)：跟着 PC 动（局部零偏移）
 │    └─ 物品实体 Item { kind }           ← EquippedTo(slot)：逻辑归属
 └─ EquipmentBonus（加成之和）            ← 本域是**唯一**写入者
```

## 二、三个实体角色

| 角色 | 是不是实体 | 关系 | 为什么 |
| :--- | :--- | :--- | :--- |
| **槽位** | 是 | `ChildOf(pc)` | PC 的物理延伸；跟着 PC 走是空间事实 |
| **物品** | 是 | `EquippedTo(slot)` + `ChildOf(slot)` | 逻辑归属（卸下时要活着）+ 空间附着（跟着动） |
| **加成** | 否（组件） | — | 见第五节 |

槽位的 `Transform` 与物品的 `Transform` **都是局部零偏移**：单位根节点就是脚底
（见 `spawn/unit.rs`），所以「物品的世界坐标 = PC 的世界坐标」天然成立。

## 三、槽位集合 ✅ **已定：三个槽**

| 槽位 | 提供什么 | 起始装备 |
| :--- | :--- | :--- |
| `MainHand` 主手 | 动作节奏偏移 + 伤害 | 铁剑（伤害 +1、前摇 −0.05s） |
| `OffHand` 副手 | 格挡率 + 护甲 | 圆盾（格挡 0.35、护甲 +1） |
| `Armor` 身甲 | 护甲 | 锁子甲（护甲 +1） |

**`Trinket`（饰品）没做**：它改的是资源线（Focus 上限 / 回复速率）而不是战斗数值，
属于另一条玩法线。触发条件：出现"改资源"的装备需求，或 Focus 从时间线搬进 combat。

## 四、穿脱

**穿上**：物品实体带着 `EquippedTo(slot)` + `ChildOf(slot)` 出生（都在场景工厂里）。
**卸下**：断两者 + **把当前世界坐标写回 `Transform`**。

第三步是设计稿里预告的"最容易忘的一步"，实测**确实**是——而且我第一版忘了它，
是**实机探针**抓出来的（见第七节）。它必做的原因：物品的 `Transform` 是局部零偏移，
解除 `ChildOf` 之后父级变换不再作用，那个零偏移就字面地变成世界坐标，物品跳到原点。

**校验只有一个入口**：`On<Insert, EquippedTo>` 的 Observer。任何来源的装备
（玩家 / 脚本 / AI）都过它，装错槽当场退还并写一条 `EquipmentRefused`
（走与 `ActionBlocked` / `BlockRefused` 同一条提示条）。

## 五、属性叠加 ✅ **已定：基础值 + 加成**（设计稿的"候选 B"）

```text
基础值（组装层写，装备从不碰）  +  加成（equipment 域唯一写入）  =  有效值
   Armor(1)                          EquipmentBonus(armor: 2)          armor 3
   BlockChance(0.0)                  EquipmentBonus(block: 0.35)       block 0.35
```

读取侧统一走纯函数（`equipment::domain`，**零 Bevy、可脱离 App 单测**）：
`effective_armor` / `effective_block_chance` / `effective_windup` / `weapon_damage`。

**为什么是这个形状**：加成是**每帧重算**的（从槽位 → 物品遍历），于是
「卸下要减多少」这个记账问题**根本不存在**——重算是幂等的，清空再加一遍结果相同。
基础值也永远查得到（"没穿装备时我是什么样"）。

### ⚠️ 与设计稿的一处偏差：加成是一个聚合组件，不是四个

设计稿的候选 B 写的是"每个可被装备影响的属性各拆成 `BaseX` + `XBonus` 两个组件"。
落地时改成**一份聚合** `EquipmentBonus(ItemBonus { armor, damage, windup_delta, block_chance })`。

理由：**没有任何消费者需要"单看某一项加成"**——命中公式要的是有效护甲、
攻击执行器要的是伤害加成，两者都只读一个数。拆成四个组件只会多三份写入者、
三处同步点与三次"清残留"的机会。而设计稿担心的"基础值被覆盖"这件事，
由"本域从不写 `Armor` / `BlockChance`"这条纪律保证，与拆几个组件无关。

**触发条件**（满足任一条就拆开）：① 出现**第二种加成来源**（Buff / 光环）需要
各自追踪；② 出现"只清掉装备给的某一项"的玩法。届时聚合 → 分项的迁移是局部的。

## 六、装备"提供"什么：数据来源，不是新机制

| 装备提供 | 效果 | 落到哪儿 |
| :--- | :--- | :--- |
| 动作节奏 | 武器决定动作节奏 | 声明时经 `equipment::weapon_timing` 加偏移 |
| 伤害 | 攻击数值 | 攻击实体生成时经 `equipment::weapon_damage` 加 |
| 抗性 | 护甲 / 格挡率 | 命中公式读 `armor_of` / `block_chance_of` |

**攻击实体自己不认识"装备"**：伤害加成在**生成那一刻**算好写进 `PhysicalDamage`，
于是目标获取 / 命中管线 / 爆炸结算全部一行不用改。

## 七、武器决定动作节奏 ✅ **已定：给偏移**（设计稿的"乙"）

`weapon_timing(base, bonus)` 只改前摇，且**永不为负**（负数前摇会让 `execute_at`
落在声明之前——那一手"倒退到过去"，整机级 bug）。

⚠️ **只有攻击动作吃武器节奏**：移动 / 跳跃 / 翻滚的节奏与手上的东西无关，
让一把剑改掉翻滚的前摇没有道理。三个攻击声明系统显式调用它，移动系的三个不调。

### ⚠️ 实机探针抓到的两个 bug（单测都测不出来）

1. **物品位置被父级叠了一次**：物品挂 `ChildOf(slot)`，而槽位/物品的 `Transform`
   我一开始写了**世界坐标**——于是 `GlobalTransform` = 槽位(世界) + 物品(世界)，
   物品落在 `2×` PC 位置。实机读数：PC `(3,-1,1)`、物品 `(6,-2,2)`。
   修法：两者都改成**局部零偏移**。
2. **起始装备每帧都发**：`equip_starting_gear_system` 只认 `With<InputDriven>`，
   而玩家身上**没有**槽位组件（槽位是子实体），于是判据永远为真、每帧发一整套。
   实机读数：护甲两帧就翻倍。修法：判据改成"玩家名下有没有 `EquipmentSlot` 子实体"。

两条都是**只有跑起来才看得见**的：单测里我造的单位没有父级链 / 只跑一两帧。

## 八、与 `config/` 的分工

| 数值 | 住哪 | 为什么 |
| :--- | :--- | :--- |
| 技能的**基础**前摇 / 后摇 / 消耗 | `config/actions.ron` | 全局设计数据，与具体武器无关 |
| 武器的**偏移** | `ItemKind::bonus()`（`src/equipment/components.rs`） | 属于那一件物品 |
| 单位的**基础**护甲 / 血量 | 组装层（`spawn/`） | 与角色相关，不是技能也不是装备 |

**不要把一个数值同时放进两处**——本项目反复踩过的坑。

物品定义**暂留在代码里**（没外置成 `config/items.ron`）：现在只有三件起始装备、
人手一件；真正需要 `.ron` 的是"掉落 / 商店"那种**随机生成**的场景。

## 十、落地顺序（实际走的）

```text
① equipment::domain 的纯函数（基础 + 加成、前摇不为负） ✅
② 槽位 + EquippedTo + 类型校验 Observer                    ✅
③ 穿脱与重算（recompute 幂等，从槽位出发）                  ✅
④ 武器改节奏 + 武器改伤害                                   ✅
⑤ 组装层穿起始装备 + HUD 显示有效护甲 + BRP 可读             ✅
```

`equipment` 是**独立域**（不是 `combat` 的子域）：槽位 / 物品 / 穿脱不是战斗概念
（背包、掉落也要用它），而 `combat` 已经有 8 个子域了。
