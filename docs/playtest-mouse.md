# 真人鼠标一遍过（约 10 分钟）

**为什么需要你**：BRP 的合成光标**驱动不了 Bevy 的 UI 焦点**——所有 7 个 HUD 区域根节点的
`RelativeCursorPosition { cursor_over: false }`，`PointerOverUi` 永远是 `false`，
所以"UI 吃不吃点击""悬停变不变样"这类断言**只能用人手验证**（不是没来得及验，
是那条路验不了，见 [`playtest-checklist.md`](playtest-checklist.md) 第 3 节）。

**怎么跑**：仓库根目录 `cargo run`，**不需要** BRP / MCP。
下面每一条**只看画面**就能判断；把"看到什么"如实写回即可——
**"什么都没发生"也是一个有效结果**，很可能就是真 bug。

> 小提醒：本项目的按键**松手按时钟计**，世界冻着时松手可能不到点，
> 于是**同一个键按第二次会没反应**。按键不灵时，先按一下**空格**让世界跑一秒再试。

## 想更硬的话：让眼睛和 BRP 互相作证

`cursor_over` 这类值**BRP 读得到**（读不到的只是"合成光标能不能触发它"）。
所以你可以**一边压着真鼠标，一边让我读**——两份证据互相印证：

1. 你把真鼠标**压住某个面板不放**（例如技能栏上），**别动**；
2. 跟我说一声"压在技能栏上"；
3. 我立刻用 BRP 读三样东西：
   - `PointerOverUi`（应为 `true`）
   - `HoveredCell`（应为 `None`）
   - 7 个 HUD 区域根节点的 `cursor_over`（被压的那块应为 `true`）

**为什么这比只看画面硬**：我这轮已经吃过一次教训——
"探点全落空"被我读成"悬停坏了"，其实是**探点没落在地形上**。
眼睛说"变灰了"、BRP 说 `cursor_over: false`，两者一致才算数；
不一致本身就是最有价值的发现。

（**注意**：这一步**只在你方便时**做。纯看画面也能完成清单，
只是"变红了没有"这类判断多一层人眼的不确定。）
