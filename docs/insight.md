# 时间轴与洞察力（信息层面板设计稿）

> ⚠️ **这一版是设计，代码未落地**。栏目：✅ = 已有、🚧 = 本文新定、
> ❓ = **需要你拍板**。
>
> 已有的时间轴见 `src/presentation/hud/timeline/`（三条车道 + 色块 + 候场区）；
> 本文要加的是**交互**（悬停看细节 + 高亮对应单位）与**洞察力读数**。

## 一、要解决什么

游戏的核心是**预读博弈**：读敌人的前摇，决定打 / 走 / 防。现在时间轴能看出
"谁在什么时候动手"，但看不出**"谁要干什么、打哪儿"**——那正是玩家要预读的东西。
这一版把它补齐，并让"看时间轴"与"看战场"连起来。

```text
现在：色块 = 某人在某个时刻有事发生        （知道"什么时候"，不知道"干什么"）
要加：悬停色块 → 谁 · 什么技能 · 打哪一格 · 还有多久
     同时战场上对应的单位被高亮            （把时间轴与战场连起来）
```

## 二、悬停一条事件：看到什么

鼠标滑到某个色块上，弹出一个**读数条**（复用现有的提示条：

| 字段 | 例子 | 为什么玩家要看 |
| :--- | :--- | :--- |
| **谁** | `ENEMY` | 是谁要动 |
| **什么** | `fireball` | 这一手是什么（决定"我该躲还是该挡"） |
| **打哪** | `cell (3,1)` + 战场高亮 | **落点**——判断"我站的地方安不安全" |
| **还剩多久** | `resolves in 0.4s` | 前摇倒计时，与敌人面板上的读数同源 |
| **能不能被打断** | `interruptible` / `super armor` | 决定"抢一手打掉它"值不值 |

**数据从哪来**（不新增机制，全是已有组件）：

```text
色块（TimelineSlot）──┐
                      ├─▶ 悬停读数：ActionTiming + 载荷名 + Target/Threatens + execute_at
行动实体 ─────────────┘
```

- `ActionTiming` → 前摇 / 后摇（→ "还剩多久"）
- 载荷标记（`MeleeAction` / `FireballAction` / …）→ **什么**（表现层已有
  `payload_name`，见 `presentation/hud/actions.rs`，直接复用）
- `TargetCell` / `Threatens` → **打哪**（`Threatens.cells` 就是"这一手威胁到哪些格"）
- `CombatTags` → **能不能被打断**（`interruptible` / `super_armor`）

**因此不新增数据类型**，只是把已经挂在行动实体上的东西读出来。这是本项目一贯的做法
（见 `docs/skills.md`：技能定义是静态数据，运行时状态全在行动实体上）。

## 三、高亮：把时间轴与战场连起来

悬停色块时，战场上对应的东西高亮：

| 悬停目标 | 高亮什么 | 用什么 |
| :--- | :--- | :--- |
| **色块**（某个单位的一手） | 那个**单位** | 单位脚下放一圈指示 |
| **落点格** | 目标格 / 威胁格 | 已有的 `HoverHighlight` 那套（改颜色） |

**注意**：现在 `HoverHighlight` 只有一个，由鼠标位置驱动（`HoveredCell`）。
悬停时间轴时鼠标不在战场上，所以要**两条来源**：

```text
鼠标在战场上 ─▶ HoveredCell（已有）
鼠标在时间轴上 ─▶ TimelineHover { lane, entity }（新增）
                        ↓ 两者都不写游戏状态，只产出"这一帧高亮什么"
                  HighlightTarget（表现层合并后画）
```

❓ **优先权**：两者同时存在时（鼠标在时间轴上，但战场里也有个残留高亮）**以时间轴为准**——
这是玩家的注意力所在。你如果觉得该反过来，说一声。

## 四、洞察力面板 ❓ **需要你定范围**

`game-design.md` 说"信息即力量：升级 = 获得洞察力 / 信息权限"。面板要能显示：

| 读数 | 现在有吗 | 说明 |
| :--- | :--- | :--- |
| 血量 / 精力 | ✅ 敌人面板已有 | |
| **速度帧**（谁先动） | ✅ 数据有（`AttackFrame`），**预演读数已显示** | 洞察力的第一个读数 |
| **射程** | ✅ `AttackRange` | |
| **打断抗性** | ✅ `ActionTiming.interrupt_resist` | **这是"我能不能打断它"的关键数** |
| **会什么技能** | ✅ 技能目录 | 敌人当前会哪些能力 |

**三种范围，你挑一个**：

| 方案 | 内容 | 代价 |
| :--- | :--- | :--- |
| **甲：悬停读数（最小）** | 只做第二节那个读数条 | 最省；但"信息即力量"只落了一半 |
| **乙：敌人详情面板** | 敌人面板展开，列出上面五个读数 | 中等；需要一个"展开 / 收起"交互 |
| **丙：完整洞察力系统** | 加上"未解锁时看不到"的权限机制 | 大；属于 roguelike 成长线，**本轮范围之外** |

**我建议乙**：它把"信息即力量"变成看得见的东西，而不引入成长系统
（那是另一条线，`game-design.md` 也只有总纲）。**甲是底线，丙要等成长线。**

## 五、为什么这让"预读"成立（设计意图）

现在玩家能预读的只有"敌人什么时候动手"。加上落点与打断抗性之后，
同一个时间轴能回答三个问题：

```text
① 它什么时候打到我      → 我该不该现在走
② 它打到哪一格          → 我走的哪一格是安全的
③ 它能不能被打断        → 我该躲，还是该抢一手打掉它
```

**② 是现在最缺的**：火球锁格（`TargetCell` 就是它锁的格），所以"往旁边走一步就安全"
这件事现在**玩家看不出来**。这正是 `docs/combat.md` 说的"锁格 + 真实距离"那条
设计在**信息层**的兑现。

## 六、落地顺序 ✅ **①② 已落地**（2026-09-25）

```text
① 悬停识别：时间轴色块要能认出来（现在是纯 UI 节点，要挂 `Interaction`）   ✅
② 读数条：复用 `payload_name` + `ActionTiming` + `Threatens`（纯函数，可单测） ✅
③ 高亮：`TimelineHover` → 单位指示圈（与 `HoveredCell` 合并，注意优先权）    ✅
④ 洞察力面板（若选乙）：敌人面板加"详情"区，列五个读数                       🚧
```

**①②③ 不新增领域、不新增数据类型**，都在 `presentation/hud/timeline/` 里做完
（`model` / `readout` 纯函数 / `scene` 夹具 / `system` 取数写 UI，三层照旧）。
④ 也只在 `presentation`。

### 已落地的部分

- 色块挂上了 `Interaction`；**它还带着自己那条行动实体的 id**
  （`TimelineSlot::action`）——读数要的五个数全在那上面，悬停时**反查**即可，
  不必全表扫描"哪个行动属于这条车道"（那种扫描的判据会与分道逻辑分叉）。
- `readout.rs` 的 `readout_line` 是纯函数：
  `ENEMY · fireball → cell (3,1) · 0.4s · interruptible`。
  **对抗标签的读法与打断闸门共用一条口径**（`!interruptible || super_armor`
  = `super armor`）——读数说能打断、实际断不掉比没有读数更糟，有一条测试专门钉这个。
- 读数条挂在时间轴状态行**正下方**（不是复用"无法操作"提示条：那条在玩家面板上方，
  离眼睛看的地方太远）。
- **战场指示圈已接**：悬停色块时，那一手的**主人**脚下出现一个琥珀色圆环
  （`TimelineFocusRing`，世界空间、平铺在地表上、默认隐藏）。圈在**脚底的高度**上，
  所以单位跳起来时圈留在地上（高度由阴影表达）。
  它和鼠标驱动的 `HoveredCell` 是**两套不同的高亮**（一个圈格、一个圈人），
  所以没有合并逻辑——时间轴悬停时鼠标本来就不在战场上。

### 与设计稿的两处偏差

1. **读数条显示的是"前摇剩余秒数"**，不是设计稿第二节表格里的"前摇 / 后摇"那两个数
   ——剩余秒数才是"来不来得及走"的读数；总时长在色块宽度里已经看得见
   （块宽 = 前摇 + 后摇）。
2. **`Threatens` 只取了最后一格**（落点），不是整条威胁格列表。设计稿第四节的
   "画威胁格"**仍未做**：它需要一套格子高亮的合并逻辑（与鼠标的 `HoveredCell`
   抢通道），而第 ③ 步实际做的是"圈人"——一个圈格、一个圈人，两套高亮不冲突，
   于是不必合并。现在火球锁的格（`TargetCell`）与横扫的扇形终点都能读出来，
   已经覆盖了"打哪儿"这个问题的 80%。

| 1 | 洞察力面板的范围 | **乙：敌人面板展开详情**（甲是底线，丙留到成长线） |
| 2 | 悬停优先权 | **时间轴压过战场**（已写进 `TimelineHover` 的说明，第 ③ 步接高亮时生效） |
| 3 | 读数条放哪 | 已落在**时间轴自己的状态行下方**（原建议是复用提示条，实际放这里离色块更近） |
| 4 | 要不要画"威胁格" | **要**——留到第 ③ 步（与单位高亮同一套合并逻辑） |

第 4 条多说一句：`Threatens.cells` 现在同时被**反应系统**（决定要不要冻结世界）
和 **AI**（决定要不要躲）读，唯独**玩家看不见**。把同一份数据画出来，
玩家看到的威胁图与 AI 用的是同一张——这正是"AI 与玩家对称"那条设计的兑现。
