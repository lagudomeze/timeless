- [x] **#56 单位辨识度低：世界里没有阵营标识**（已修）
      **现象**：`player.png` 与 `enemy.png` 是两张不同贴图（代码正确），但 16×16 像素图
      拉到 1.8 世界单位、配上斜视角与方向光后，两个单位都读成"暗色小块 + 一个亮脸"，
      **很难一眼分清谁是谁**；阵营色只存在于 HUD 与时间轴，世界里没有任何提示。
      在一个"读意图"的游戏里，"哪个是我、哪个是它"是**每帧都要用的信息**。
      **改法（已落地）**：`presentation/unit_sprite.rs` 加 `FactionRing` 标记 +
      三个几何旋钮（内半径 1.05 / 外半径 1.25 / 抬升 0.03）与 `faction_ring_color()`
      （**与 HUD 的 `faction_color_alpha` 同一份真相**，改了 HUD 阵营色世界里的环跟着变）；
      环在 `spawn/unit.rs` 里作为单位实体的**第三个子节点**挂上（`Annulus` + 平铺旋转 +
      `NotShadowCaster`）。它是**静态**的——跟着单位的 `Transform` 走就够了，不需要系统
      （与阴影不同：阴影要贴地、要随离地高度收缩）。
      ⚠️ 单位根节点的约定不变：**脚底 + 无旋转 + 无缩放**，环自己带平铺旋转与抬升。
      **验收**：
      `assembled_units_carry_a_faction_sprite_and_a_ground_shadow`（扩展：三个单位各有一个环、
      材质底色 == `faction_ring_color(自己的阵营)`、局部平移 == 抬升量）、
      `the_two_factions_get_different_ring_colours`（**同色等于没做**，而"有个环"很容易蒙过截图）、
      `the_ring_clears_the_shadow_and_stays_inside_a_cell`（内半径 ≥ 阴影半径、外半径 < 一格、
      抬升 > 阴影抬升——三条旋钮约定）。⚠️ 那三条比较的是常量，用 `black_box` 把值藏起来，
      否则 clippy 会说"断言的值恒定"（它是对的：常量本身不是测试，**改了常量这里会红**才是）。
      **实机**：玩家脚下一圈**蓝**环、两个敌人**红**环，都让开了阴影（截图见 CHANGELOG）；
      BRP：`world.query FactionRing` → **3 个**，`Transform` 为 `(0, 0.03, 0)` + 绕 X -90°。
      **顺带修了一个 BRP 坑**：`FactionRing` / `UnitSprite` / `UnitShadow` 原先没派生
      `Reflect`，`world.query` **静默返回 0**（画面上明明有环）——现在三个都注册了，
      这正是 [`clock.md`](clock.md) #62 那条"查不到 ≠ 不存在"的又一次实证。
      **未做**：威胁**来源圈**（#57 剩下的那一半）现在可以复用同一个零件了；
      纸片对比度（换个更清楚的素材 / 垫描边）还没动——环先解决了"哪个是我"。

- [x] **[P2][feat] 伤害数字：受击反馈的最后一环**（已修）
      **已做**：① 命中处冒一小簇短命粒子（颜色取**被打中那一方**的阵营色）；
      ② `DamageEvent.at` / `DeathEvent.at` 带虚拟时刻，日志行前缀 `[1.2s]`；
      ③ **伤害数字**（本次）：受击单位上方飘出 `-12`，0.8s 内上浮 + 淡出。
      **实现**：`presentation/effects.rs` 里加 `DamageNumber` 组件 +
      `animate_damage_numbers_system`，用 `Text2d`（世界空间文字）——与粒子**并列**：
      两者都只读 `DamageEvent`，都在同一次命中里生成，都**自己收尾**。
      字体走新资源 `EffectFont`（由 `setup_hud` 把 HUD 那份字体塞进去）：
      造文字的系统在 `Update` 里按事件现场建实体，手里只有 `AssetServer`，
      不该在那里 `.load()`。
      **两个刻意的选择**：读的是 `DamageEvent.amount`（**已经算完护甲 / 格挡 / 招架的
      真实掉血**，不是任何"预计伤害"）；**走 `Time<Virtual>`**——世界冻结时它定格在
      "刚打中"的样子，玩家解冻后接着看完。用真实时间的话，等玩家思考时数字自己飘走了，
      偏偏在最需要它的时候消失。
      **淡出而不是缩小**：数字要读得完，缩小会让最该看清的那一帧最小。
      **验收**：`a_hit_floats_the_damage_it_dealt`（数值 == 这一击的结算值）、
      `the_damage_number_rises_fades_and_cleans_itself_up`（上浮 / 淡出 / 自己销毁，
      且刚冒出来时完全不透明）、`a_hit_on_a_gone_target_leaves_no_number`（同帧阵亡不 panic）。
      ⚠️ **实机待补**：截图需在冻结世界里打出一击（这正是本条的验收重点）。
      **未做（本条之外）**：施法 / 落地反馈（脚下闪一格、落点扩散圈）与相机震动——
      它们与下面的"命中定帧"是同一批。✅ "冻结时视觉纪律"表已于 2026-09-27 定稿
      （[`../timeline.md`](../timeline.md) 第五节），**这批不再被它挡住**。

- [ ] **[P3][feat] 命中定帧（Hit Stop）与受击闪白**（原 issue #60 可选部分 + 核查建议，**未拍板**）

      所以**做这件事不再需要重新讨论时钟**，只剩幅度一个决定。
      **触发条件**：等"伤害数字 + 阵营环"落地、确认画面已经能读，再考虑加定帧；
      现在加只是让冻结状态更难读。
